# 概要

本システムは、実家の事業の一つであるアクセサリー事業における在庫・売上管理の課題を解決することを目的に開発した在庫管理システムです。  
従来の運用では、材料の在庫、商品の情報、売上データがそれぞれ別々に管理されており、データ同士が結びついていない状態でした。  

その結果、以下の課題が発生していました。

- 在庫不足時に影響する商品を即座に特定できない
- 商品ごとの売上状況が把握できず、分析ができない
- 複数のデータを照合する必要があり、業務に時間がかかる
- 経験や勘に依存した発注・商品管理が行われている

これらの業務は主にExcelや紙で管理されており、商品数（約500点）・材料数（約2000種）といった規模により、商品と材料の関係を横断的に扱うことが困難な状態でした。

さらに、Excelでもデータの統合自体は可能であるものの、以下の課題がありました。

- 商品・材料・売上といった複数データの関係性を一貫して管理することが難しい
- 在庫不足時の影響範囲特定などの処理を自動化しにくく、手作業に依存しやすい

これらの理由から、継続的な運用を行う上で課題があると考えられました。

本プロジェクトでは、分断されたデータを統合するとともに、利用者ごとの判断や作業手順に依存しない形で業務を標準化し、「商品」「材料」「売上」を一元的に管理できる仕組みの構築を目指しました。

具体的には、現在は商品および在庫情報を中心に、IDベースで管理する在庫管理システムを実装しており、在庫更新や商品検索、データ保存などの基本機能を備えています。

売上管理機能については、今後の拡張として設計段階まで進めており、商品ごとの販売データを蓄積・分析できるようにすることで、より高度な意思決定支援を実現する予定です。

# 背景・課題

本システムは、実家の事業における在庫管理および売上管理の非効率と、収益改善の必要性を背景として開発を行いました。

対象となるアクセサリー事業は開始から数年が経過しており、今後は本事業の収益性を高めていく方針となっています。

しかし現状では、以下の規模のデータを扱う中で、適切な管理・活用ができておらず、収益改善に向けた意思決定が困難な状態となっていました。

- 材料：約2000種類
- 商品：約500点

従来の運用では、以下のようにデータが分散して管理されていました。

- 材料の在庫：Excelで管理
- 商品情報：ECサイトごとに管理
- 売上データ：紙ベースで保管

このような状況により、以下の課題が発生していました。

## データ分断による管理の非効率

- 材料と商品の紐づけがされておらず、在庫不足時に影響する商品を即座に特定できない
- 商品ごとの売上データが整理されておらず、売れ筋分析ができない

---

## 手作業による業務負担

- 材料が欠品した際、該当する商品を約500点の中から目視で特定し、商品の出品を停止する必要がある
- ECサイトごとの商品管理状況を横断的に把握できない

---

## 属人化した運用

- Excelや紙による管理が中心であり、作業手順や管理方法が統一されていないため、業務が属人化している
- 商品ごとの売上や利益を把握するためには、複数の紙資料とExcelデータを照合する必要があり、その手順を理解しているのが実質的に1名に限られている
- そのため、経営に関わる重要な情報をその1人しか正確に把握できておらず、また把握にも時間を要する状態となっている

---

## 収益改善に向けた意思決定の課題

- 売上データが整理されておらず、売れ筋商品や不良在庫の把握ができていない
- その結果、売れていない商品が販売され続け、新商品も増え続けることで、商品数が経営に見合わない状態となっている
- 在庫状況や販売状況に基づいた発注判断ができず、経験や勘に依存している

---

これらの課題は、データの分断および業務の属人化に起因しており、収益改善に向けた継続的な運用を行う上で大きな障害となっていました。

# 解決方法（設計・工夫）

本システムでは、データの分断および属人化した運用の解消を最終的な目標とし、その基盤となるデータを一元的に扱うための管理基盤の構築に取り組みました。

本来解決すべき課題は、「商品」と「材料」の関係性を管理し、在庫と販売を連動させることにあります。しかし、従来の運用ではデータが分散しており、このような構造を実現するための基盤が存在していませんでした。

そこで本開発では、まず商品情報をIDベースで管理する仕組みを構築しました。商品名は変更や重複の可能性がある一方で、IDは一意かつ不変の識別子として扱えるため、安定したデータ管理を実現するためにIDによる管理を採用しています。

また、商品検索や更新処理を効率的に行うために、データ構造としてHashMapを採用しました。キーから直接データへアクセスできる特性を活かすことで、高速な検索処理を実現しています。さらに、名前からIDを取得する処理と、IDから商品データを管理する処理を分離することで、検索の柔軟性とデータ管理の安定性を両立する設計としました。

在庫の追加・削減や商品検索といった基本的な操作については、システム上で扱えるように実装しました。これらはExcelでも実現可能な機能ではありますが、本システムでは今後の機能拡張を見据え、データ操作をプログラム上で一元的に扱うための基盤として位置付けています。

加えて、データをファイルとして保存・読み込みできるようにすることで、システムを継続的に運用できる状態を実現しています。

なお、商品と材料の紐づけや売上データの管理については、本システムの拡張として設計を進めており、将来的には在庫と販売を連動させた管理およびデータ分析を可能にすることを目指しています。

本開発は、現状の課題を踏まえた上で、段階的にシステムを構築していくプロセスの第一段階として位置付けています。

# 実装機能

本システムでは、在庫管理の基盤構築を目的として、以下の機能を実装しました。

## 商品管理

- 商品の登録（商品名・価格・在庫数）
- 商品情報の一覧表示
- 商品名による検索
- 商品名の変更
- 商品の削除
- 在庫切れの商品一覧表示

---

## 在庫管理

- 在庫数の追加・削減

---

## データ永続化

- 商品データのファイル保存
- ファイルからのデータ読み込み

---

## 設計上の工夫

- 商品をIDで管理することによる一意性の確保
- HashMapを用いた高速な検索処理の実現
- 名前検索用とデータ管理用でMapを分離した構造

# 工夫・学習プロセス

本プロジェクトでは、Javaおよびオブジェクト指向設計に関して実務レベルの開発経験がない状態から着手したため、技術のキャッチアップと設計の理解を並行して進める必要がありました。

そこで、実装を小さな単位に分解し、「動作する最小構成の実装 → 問題点の洗い出し → 設計の見直し」というサイクルを繰り返すことで、段階的にシステムを構築しました。

当初はリスト構造で商品データを管理していましたが、検索処理の実装を進める中で、より効率的にデータを扱う方法があるのではないかと考えました。その際、大学の授業で学んだハッシュ関数をうまく使えないかと思い、調べた結果、キーから直接データにアクセスできるHashMapの特性が本システムに適していると判断し、データ構造を変更しました。これにより、検索処理の簡略化と高速化を実現しています。また、この経験から、データ構造の選択がシステム全体の使いやすさや拡張性に大きく影響することを学びました。

また、商品管理においては、名前ではなくIDによる管理へと設計を変更しました。商品名は変更や重複の可能性があるため識別子として不適切であると判断し、一意かつ不変なIDで管理することで、安定したデータ管理を実現しています。さらに、名前からIDを取得する処理と、IDから商品データを管理する処理を分離することで、検索の柔軟性とデータ管理の安定性を両立しました。

開発にあたっては事前に業務フローのヒアリングを行い全体像を把握した上で着手しましたが、実装を進める中で詳細な運用について追加で確認を行いながら進めました。その結果、実際の業務においても材料ごとにIDが付与されていることが分かり、本設計が現場の運用とも整合していることを確認できました。

また、技術的な不明点については外部リソースも活用しながら具体的な動作や仕組みを理解し、単なる実装にとどまらず「なぜその設計になるのか」を意識して学習を進めました。

設計と実装を往復しながら改善を重ねることで、単なる機能開発にとどまらず、実運用を見据えたシステム設計の重要性を理解しました。

# 今後の展望

本システムは現在、在庫管理の基盤となる機能の実装まで完了しており、今後は実際の業務課題の解決に向けた機能拡張を進めていく予定です。

まず、「商品」と「材料」の紐づけ機能を実装することで、商品の在庫変動に応じて材料の在庫が自動的に更新される仕組みを構築したいと考えています。これにより、在庫不足時に影響する商品を即座に特定できるようにし、手作業による確認作業の削減を目指します。

次に、商品ごとの売上データを管理・分析する機能を実装し、売れ筋商品の把握や不良在庫の特定を可能にしたいと考えています。これにより、データに基づいた商品展開や在庫管理を実現し、収益改善につなげることを目指します。

さらに、材料在庫に対するアラート機能の実装や、発注判断を支援する仕組みの導入に加え、先入先出法による在庫評価および原価計算に対応した会計処理の実装も検討しています。これにより、在庫管理と会計情報を連動させ、より正確な利益把握を可能にしたいと考えています。

また、ECサイトごとに取り扱う商品の違いを管理できるようにし、どの商品がどのECサイトで販売されているかを一元的に把握できる仕組みの構築も検討しています。これにより、販売状況の可視化と運用管理の効率化を実現したいと考えています。

将来的には、これらの機能を統合し、在庫・販売・仕入れを一元的に管理できるシステムへと発展させることで、継続的な業務改善と意思決定の高度化に貢献したいと考えています。

# 在庫管理システム

Javaで開発している、CLIベースの在庫管理システムです。

実家のアクセサリー事業で扱う商品・材料・在庫・レシピ・ECサイト別販売情報を整理し、将来的には売上分析や発注判断支援までつなげることを目指して開発しています。

現在は、商品管理、材料管理、レシピ管理、ECサイト管理、材料切れ時の影響商品検索などを中心に実装しています。

---

## 背景

実家では、アクセサリーの制作・販売を行っており、商品数は約500点、材料数は約2000種類あります。

商品数や材料数が増えるにつれて、在庫、材料、商品、販売状況、売上などの情報を別々に確認する負担が大きくなっていました。材料在庫はExcel、売上情報は紙、商品や販売状況はECサイトごとに管理されており、必要な情報を一つの流れで確認しにくい状態でした。

開発のきっかけは、材料が切れたときに、その材料を使っている商品を探し、ECサイト上で販売停止する作業に時間がかかっている様子を見たことです。商品と材料の対応関係がすぐに一覧で確認できないため、商品の写真や記憶を頼りに確認する必要がありました。

また、材料を発注する際には、送料を抑えるために一定額以上をまとめて注文する必要があります。しかし、どの材料がどの商品に使われているか、どの商品が売れているか、どの程度在庫を持つべきかをまとめて判断できる仕組みはまだ十分ではありませんでした。

そのため、単に在庫数を記録するだけでなく、商品・材料・販売状況・売上情報を結びつけ、将来的には発注判断や商品展開の見直しにも使える仕組みが必要だと考えました。

---

## 目的

このシステムの最終的な目的は、アクセサリー事業に関する情報を整理し、日々の作業負担を減らすだけでなく、販売・発注・商品管理の判断をしやすくすることです。

現在は、商品・材料・レシピ・ECサイト別販売情報を管理する基盤を作っています。今後は、売上情報や仕入れ情報も扱えるようにし、どの商品が売れているのか、どの材料をどれくらい発注すべきか、どの商品を継続・見直しすべきかを判断しやすい形に発展させたいと考えています。

将来的には、蓄積したデータをもとに、AIやデータ分析を活用して、売れ筋商品の傾向分析、発注判断支援、販売最適化、帳簿・確定申告への活用までつなげることを目指しています。

ただし、これらは今後の開発目標であり、現時点ですべてを実装しているわけではありません。現在は、その前段階として、商品・材料・レシピ・ECサイト別販売情報を扱うCLI版を開発しています。

---

## 解決したい課題

- 材料切れ時に、その材料を使っている商品をすぐに特定できない
- 商品と材料の対応関係が一部の人の記憶や経験に依存している
- 商品情報、材料情報、売上情報、ECサイトごとの販売状況が分かれている
- ECサイトごとの販売中・販売停止の状態を横断的に確認しにくい
- 発注判断が経験や勘に頼りやすい
- 売れ筋商品や不良在庫を把握し、商品展開を見直すためのデータ基盤がまだ整っていない

## コードの構成

```text
src/在庫管理システム/
├── Main.java
├── Product.java
├── ProductRepository.java
├── ProductService.java
├── InventoryCLI.java
├── Material.java
├── MaterialRepository.java
├── MaterialInventoryCLI.java
├── MaterialManagement.java
├── Recipe.java
├── RecipeRepository.java
├── RecipeCLI.java
├── EcSite.java
├── EcSiteRepository.java
├── EcSiteCLI.java
├── EcListing.java
├── EcListingRepository.java
└── AnalysisCLI.java
```

コードは、扱うデータごとにクラスを分けています。

`Product`、`Material`、`EcSite` は、それぞれ商品・材料・ECサイトの情報を表すクラスです。複数のデータを管理する処理は、`ProductRepository`、`MaterialRepository`、`EcSiteRepository` などに分けています。

商品と材料の関係は、`Recipe` と `MaterialManagement` で管理しています。一つの商品に複数の材料が使われるため、商品に対して材料と使用個数を登録する形にしています。

ECサイトごとの販売情報は、`EcListing` と `EcListingRepository` で管理しています。これにより、同じ商品でも、ECサイトごとに販売状況や販売価格を分けて扱えるようにしています。

画面上の入力やメニュー表示は、`InventoryCLI`、`MaterialInventoryCLI`、`RecipeCLI`、`EcSiteCLI`、`AnalysisCLI` に分けています。`Main` では、各RepositoryとCLIを用意し、起動時の読み込み、終了時の保存、メインメニューの切り替えを行っています。

## 設計上の工夫

### 内部IDと外部IDを分けて管理

商品名や材料名は後から変更される可能性があるため、名前だけでデータを紐づけると、変更時に不整合が起きやすくなります。

そのため、システム内部で使う内部IDと、実際の運用で使う外部IDを分けています。内部IDを使って商品・材料・レシピ・ECサイト販売情報を紐づけることで、名前が変わっても関係を保ちやすくしています。

### HashMapによる検索

商品名や材料名から対象データを探す場面が多いため、HashMapを使って検索しやすい形にしています。

内部IDからデータを取得するMapと、名前から内部IDを取得するMapを用意することで、検索のしやすさとデータ管理の安定性を両立しようとしています。

### 商品と材料の多対多関係に対応

一つの商品には複数の材料が使われ、一つの材料は複数の商品に使われます。

そのため、商品と材料を直接一対一で管理するのではなく、商品ごとに材料と使用個数を登録するレシピ形式にしました。これにより、材料から影響する商品を検索する機能にもつなげています。

### ECサイト情報と販売情報を分けて管理

ECサイトそのものの情報と、各ECサイトでどの商品をいくらで販売しているか、販売中か販売停止かという情報は分けて管理しています。

これにより、同じ商品でも、ECサイトごとに販売状況や販売価格を別々に扱えるようにしています。

### CLIとデータ管理処理を分離

入力受付やメニュー表示はCLIクラスで行い、データの追加・検索・変更・削除はRepositoryクラスに寄せています。

今後GUI化やDB化を行う場合にも、すべてを作り直すのではなく、できるだけデータ管理部分を活かせる構成を目指しています。

## 実行方法

Javaがインストールされている環境で、以下のように実行できます。

```bash
javac -encoding UTF-8 -d out src/在庫管理システム/*.java
java -cp out 在庫管理システム.Main
```

Eclipseで実行する場合は、Javaプロジェクトとして読み込み、`Main.java` を実行してください。
